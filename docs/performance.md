# 性能记录

性能结果按版本和二进制哈希区分。短时采样用于观察资源占用，不代替连续操作、全屏游戏、睡眠唤醒或长期驻留验证。

## 测量方法

在 Windows 交互桌面使用自包含 Release 包，按版本与实际界面状态记录资源。每轮使用独立配置，先完成扫描和缓存预热，再按固定间隔记录进程 CPU、工作集、私有提交、私有工作集、句柄及前台状态。主界面是否创建、可见与前台分别核对，不能把启动参数直接当作实际界面状态。

先准备一份隔离测试配置 `perf-seed.json`，使用本机有效的真实应用记录，并在 `Settings` 中设置以下外观字段。`-SeedConfig` 将配置复制到本轮新建的数据目录，不替换日常配置；固定数量和外观以每轮摘要为准，此文件不随发行包提供。

```json
{
  "Opacity": 0.04,
  "ReflectionStrength": 0.72,
  "DockIconVibrancy": 0.50
}
```

```powershell
./scripts/measure-performance.ps1 -Seconds 60 -WarmupSeconds 120 -SeedConfig ./perf-seed.json
```

进行前台专项时，另加 `-ShowLaunchpad`，激活应用窗口，并核对 CSV 的 `isForeground` 和 `mainWindowVisible`。输入专项还需独立确认搜索框焦点。测量期间不悬停 Dock，不同时运行 UI 压力测试；完成界面确认后，结束持续检查控件树的自动化进程，再进行静置采样。停止检查脚本不一定结束它连接的检查进程；额外的辅助功能请求会引入开销，不能混入普通空闲基线。指针静止时的结果不代表持续移动和拖动时的峰值。

启动参数没有指定 `-ShowLaunchpad`，只代表脚本未在启动时请求打开应用库，不能证明主界面从未创建。应同时检查 `startupTelemetry`。0.10.3 的 CSV 增加 `mainWindowVisible`，表示被测主窗口是否可见，不表示它未被遮挡；旧版没有该字段时，不能仅凭 `isForeground=false` 将结果归为纯 Dock 测量。

从 0.9 起，CSV 同时记录 `hasNativeCaret`：仅对被测应用的前台 GUI 线程读取系统插入点，不读取输入内容。此值只反映原生插入点，不能独立判定 WPF 输入框的焦点；`false` 不证明搜索框失焦，焦点与中文组合输入需单独验证。

| 指标 | 含义 |
| --- | --- |
| 全机 CPU | 进程 CPU 增量 / 时间增量 / 逻辑处理器数 |
| 单核 CPU | 不除以逻辑处理器数，100% 代表一个逻辑核心持续忙碌 |
| 私有工作集 | 当前驻留在物理内存中的私有页 |
| 私有提交 | 进程提交的私有内存，与工作集不同 |
| 总工作集 | 包含共享页，不能当作私有工作集 |
| 首帧 | 应用内计时，不包含下载、解压或完整进程创建时间 |

报告位于 `artifacts/performance/<时间戳>/`，包括 `summary.json`、`samples.csv`、`binary-manifest.json`。分发报告中的机器路径使用相对名称，数值和二进制哈希不作变更。

内存表中的 MB 按 1024 × 1024 字节换算；CPU 为进程统计，不包含外部检查工具自身的 CPU。

## 解释与边界

私有工作集低于 120 MB 是优化目标；共享页、缓存、显卡驱动、显示器数量、缩放和可见窗口内容都会影响结果。当前动态透景使用系统合成，静态折射按窗口事件取样和计算；流光使用有限时长的交互动画，静止后停止。

单轮数据不能说明冷/热启动分布，也不能把版本差异归因于某一项修改。资源短期下降不证明没有泄漏。尚未提供 GPU、持续指针移动、独占全屏或过夜运行的量化结果。兼容性与验证范围见 [验证记录](validation.md)。
