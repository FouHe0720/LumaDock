# 本机性能记录与测量方法

所有性能数值必须对应实际采样文件。`scripts/measure-performance.ps1` 默认测量自包含 `artifacts/publish/LumaDock.exe`，先等待 15 秒扫描/缓存预热，然后每 5 秒采样一次，共 120 秒。每次使用独立配置目录，因此首次扫描开销可见，不会污染日常配置。

早期候选版 `artifacts/performance/20261031-121036` 的主程序集哈希为 `ABC9952B17583039D5A9BCFF4610E3B373BAD43E057C0D4E4D95DD25AE36039A`。其 90 秒启动台采样平均为全机 **3.6802294%**、单核 **58.8834882%**，私有工作集峰值 **100.250 MB**；总工作集首尾增加 13.922 MB、私有提交增加 17.903 MB。保留此记录，不作为最终版本数据。

开发诊断 `artifacts/tests/foreground-diagnostics.json` 标记为 `diagnosticOnly=true`，来自 `work/liquid-perf-probe/results.json`，不是上表的发布基线。它改变了窗口内容及原生背景：前台仅含 TextBlock 的 7 秒场景也达到单核约 12.497%，并观察到 UI Automation 监听与较多窗口查询消息。同机有开发和自动化工具，因此不是干净实验环境；这些现象不能证明外部 UIA 是唯一原因，也不能据此声称前台开销已经全部解决。

## 指标口径

| 指标 | 数据来源 | 说明 |
| --- | --- | --- |
| `startupToDockMs` | 应用 Stopwatch 至 Dock 首个 `ContentRendered` | 进程入口后的首帧时间，不含操作系统创建进程之前时间，也不代表所有应用图标已加载 |
| `scanMs` / `appCount` | 应用后台扫描计时/实际目录数量 | 首次扫描记录，随机器快捷方式/AppsFolder 数量变化 |
| `launchpadFirstFrameMs` | 打开请求至窗口渲染后回调 | 首次窗口构造和布局开销；不保证全部异步图标已返回 |
| CPU `% machine` | 进程 CPU 毫秒差 / 墙钟差 / 逻辑处理器数 | 与系统总 CPU 百分比口径一致 |
| CPU `% one core` | 进程 CPU 毫秒差 / 墙钟差 | 用于识别单核占用，避免多核平均掩盖负担 |
| Working set MB | `Process.WorkingSet64` | 当前物理驻留内存，含共享页 |
| Private bytes MB | `Process.PrivateMemorySize64` | 私有提交内存，不能拿它代替私有工作集 |
| Private working set MB | `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate` | 私有驻留工作集；WMI 不可用时记为 null，不伪造 |
| Handles / Threads | 实际进程计数 | 用于后续重复开合/长跑资源增长调查 |
| `isForeground` | 前台 HWND 所属进程与目标 PID 比较 | 当前脚本每次采样记录；旧轮次没有此列时不补造焦点状态 |
| Growth MB | 最后与最初采样差 | 小于数分钟的差值不能证明无泄漏 |

`--show-launchpad` 用于测量管理窗口打开状态。若要测空闲驻留，保持窗口关闭、鼠标离开 Dock、不要拖动图标。测试脚本本身、WMI 与同机开发工具会产生一定系统负载；脚本只统计目标进程 CPU。

## 发布前仍需的稳定性矩阵

1. 冷启动和热启动各 5 次；记录中位数及范围，不仅记录最快的一次。
2. 关闭启动台后空闲至少 10 分钟；测试系统省电/电池模式。
3. 当前 0.4 已执行 100 次真实 WPF 显示/搜索/导航/隐藏、3 次窗口重建和动画关闭中重新唤起，26.602 秒无异常（`artifacts/tests/ui-results.json`）；共记录 105 次显示/隐藏、4 次关闭。100 次循环关闭动画且禁用测试窗口输入，不能代替鼠标拖拽和完整交互验收。强制 GC 后托管堆由 10,267,640 增至 17,414,808 字节（+7,147,168）；进程采样句柄 1004→1011，采样峰值 1068。该轮存在保留堆增长，需要更长循环调查，不能证明泄漏或无泄漏；托管堆也不能代替私有工作集。
4. 2 小时和过夜驻留，持续采样；睡眠唤醒、Explorer 重启、显示器断连重连。
5. 真实全屏游戏、视频全屏、UAC/管理员应用；确保 Dock 不干扰输入且能恢复。
6. 双屏、负坐标屏幕、不同 DPI 组合；检查热区、定位、字体/图标清晰度。

当前实际完成的测量和限制以 `validation.md` 为准。未跑的场景必须保留为待验收，不能写成通过。
