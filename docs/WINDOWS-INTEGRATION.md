# Windows Shell 集成与边界

## 发现与图标

- 在 STA 中读取当前用户/公共开始菜单、当前用户/公共桌面的 `.lnk`、`.url`、`.exe`。开始菜单递归扫描并跳过重解析点；桌面只扫描顶层，不把桌面子目录中的程序收进启动台。
- `Shell.Application` 的 `shell:AppsFolder` 提供 Windows 注册应用视图，包括 Win32 和打包应用，不能把该视图的记录数当成 UWP 数量。
- 使用 Shell 名称、`System.AppUserModel.ID`、`System.Link.TargetParsingPath` 与快捷方式真实目标；不读取所有安装磁盘，也不宣称发现未注册的便携软件。便携软件可手动添加。
- 按目标路径和参数合并扫描中的重复记录，保留不同启动参数。启动 `.lnk` 时由 Shell 读取原始参数，不重复附加。
- 图标在单个后台 STA 中用 `IShellItemImageFactory` 提取，回退到 `SHGetFileInfo` 关联图标。返回冻结的 WPF 位图，释放 HBITMAP/HICON 和 COM 引用。最多保留约 256 个图标任务（短时并发请求可略超），没有图标时返回空值。
- Shell 扩展由 Windows/应用提供；存在损坏、挂起或返回缺失图标的可能。图标工作线程不阻塞主界面关闭。Shell 扫描/图标提取不会加载浏览器运行时。

## 窗口识别与切换

- 只识别真实可见、非工具、非 DWM cloaked 的顶层窗口。小圆点代表已识别的应用窗口，不代表后台服务或无窗口进程。
- `SetWinEventHook` 监听前台切换、最小化和窗口创建/销毁/显示/隐藏；140 ms 合并事件后重新枚举窗口，无周期性进程轮询。位置变化只检查前台窗口，合并后只通知界面更新全屏判定，不重新枚举进程，避免拖动窗口的无效成本。
- 查询进程可执行文件路径、进程 AUMID 与窗口 `IPropertyStore` 的 AUMID。`ApplicationFrameHost` 会进一步读取实际应用子窗口身份。
- 匹配完整可执行文件路径或完整 AUMID，不按名称猜测运行状态。同一 exe 的多个快捷方式/配置文件未必能区分；带参数的 Explorer 快捷方式不作窗口身份猜测。部分提权/受保护进程无法查询，可能没有运行圆点。
- 点击已识别应用时还原最小化窗口并请求 `SetForegroundWindow`，同应用多个窗口可循环切换。Windows 前台策略/权限隔离可能拒绝请求；返回失败，不强行注入、不伪造成功。
- AppsFolder 启动请求交给 Windows Explorer 激活；Shell 接收请求不等于目标一定成功启动。应用自身闪退、卸载残留、损坏快捷方式需由用户重新添加或重新扫描处理。
- 全屏判定比较当前前台顶层窗口与显示器完整边界，排除 Explorer 桌面/任务栏。`IsForegroundFullscreenOnMonitor(deviceName)` 仅在前台窗口覆盖 Dock 所选显示器时抑制 Dock，避免另一屏全屏时影响本屏 Dock。远程游戏、特殊合成覆盖层和独占图形程序仍需实机验证。

## 显示器与 Shell 安全

- `EnumDisplayMonitors` 与 `GetMonitorInfo` 返回物理像素的完整/工作区边界，包括负坐标。主程序应声明 PerMonitorV2，并按目标屏幕 DPI 换算 WPF DIP。显示器断开时回退主屏幕。
- Dock 使用工具窗口与 `WS_EX_NOACTIVATE`，不占任务栏条目、不抢键盘焦点，不注册 AppBar、不改变工作区、不替换任务栏。
- 桌面显隐只对 Explorer 桌面 `SysListView32` 调用 `ShowWindow`；不写注册表、不移动/删除桌面文件。该 Explorer 窗口层级并非稳定的公共桌面管理接口，找不到时明确失败。重启 Explorer 后状态可能复原；Windows“查看 → 显示桌面图标”仍是系统恢复方式。
- 开机启动只创建/移除当前用户启动文件夹中的 `LumaDock.lnk`，仅应在用户明确确认之后调用。不写 Run 注册表，不建服务/计划任务。
- 全局热键通过 `RegisterHotKey` 注册 Ctrl+Alt+Space，冲突时 `IsRegistered=false`，仍可从 Dock/托盘打开 Launchpad。退出时注销所有 WinEvent hooks 和热键。

## 本机验证

2026-10-29 的早期 Windows 11 x64 Release 探针曾发现 256 条合并应用记录、38 条桌面记录、136 个 AppsFolder 身份；当时递归扫描了桌面子目录，额外收进 95 条程序记录，现已修正。该历史探针抽样 30 条真实 Shell 图标全部提取成功（其中 28 条带 AUMID），但其 256 条数量不代表最终版本。

最终扫描修正为开始菜单递归、桌面顶层后，本机发现 **161 条应用、38 条桌面记录和 38 条桌面快捷方式关联**，AppsFolder 身份仍为 136。未修改开机启动或桌面显隐。

本机仅连接一台 2560×1440 显示器（工作区 2560×1392），多屏和混合 DPI 代码已实现接口，但无法声称已在双屏/Windows 10/全屏游戏/提权程序上通过验证。原始只读探针保存在 `work/NativeProbe`，输出含用户本地路径，只用于本机排错。

## 可重复的 Windows 集成测试

在 Windows 10/11 x64 的已登录交互桌面会话中运行，不需要 IDE 或额外 NuGet 测试框架：

```powershell
.\scripts\test-windows.ps1
```

测试项目为 `tests/LumaDock.Windows.Tests`，已加入 `LumaDock.slnx`。脚本使用项目 `.dotnet` 或系统 .NET 10 SDK，在 `artifacts/tests/windows-results.json` 写入可分享的汇总结果。报告不含应用名称、用户路径、窗口标题、AUMID 或异常堆栈；只有测试名称、耗时、数量、屏幕尺寸与失败异常类型。

五项检查分别验证：

1. 实际 Shell 扫描非空、名称与启动元数据有效、标识唯一、文件路径确实存在。
2. 当前用户/公共桌面记录指向现存的 `.lnk`、`.url` 或 `.exe`，桌面为空也可通过。
3. 从真实快捷方式和注册应用选取图标样本，异步提取出非空冻结位图，并确认缓存复用。损坏快捷方式允许小部分图标缺失，但至少需取得 8 个（样本不足时为全部样本）。
4. 原生显示器工作区尺寸有效且位于对应物理显示器范围内，允许负坐标。
5. 真实窗口快照的 HWND 唯一且身份元数据可匹配；允许没有其他可见窗口。如用户已打开计算器，额外检查其窗口身份匹配，但测试不会主动打开计算器。

测试不会启动/激活应用，不写开机启动、桌面显示或注册表，不编辑任何桌面/开始菜单快捷方式。唯一测试报告写入项目 `artifacts` 目录。Shell 中途发生安装、卸载或文件删除会改变发现结果，可待系统稳定后重跑。该脚本用于功能集成验证，不能当成长期驻留性能或全屏游戏测试。

2026-10-29 18:47（UTC+8）历史结果：5/5 通过，发现 256 条应用（桌面递归修正前），14/14 图标读取并冻结。最终扫描修正后再次运行 **5/5 通过，161 条应用、38 条桌面记录**；以 `artifacts/tests/windows-results.json` 的最新计数为准。检测到已运行的计算器时，其身份匹配通过。测试不会主动启动应用。
