# 架构与开发说明

LumaDock 是单进程、用户权限的 Windows WPF 应用，目标 `net10.0-windows` / x64。没有浏览器运行时、常驻服务、Explorer 注入或插件加载机制。

## 模块边界

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| App | 应用生命周期、托盘/热键、Dock、管理窗口、主题、设置应用 | WPF 与交互状态留在 UI 线程 |
| Core | 目录模型、稳定 ID、发现结果合并、搜索、分类建议、设置校验 | 不依赖 WPF、Shell 或磁盘 |
| Windows | Shell/COM 扫描、图标、启动、WinEvent 跟踪、屏幕及可选系统集成 | 所有本机句柄、COM 对象有释放边界 |
| Storage | JSON 读写、备份与损坏恢复、滚动日志 | 不存放机器密钥；配置版本拒绝向下覆盖 |
| Tests | 验证 Core/Storage 的业务契约 | 不更改真实桌面或启动项 |

管理窗口使用 `AppTileViewModel` 进行图标/名称的展示绑定，应用控制器集中管理命令与持久状态。部分布局和轻量交互采用代码构建 WPF 控件；这是小型应用的务实拆分，并非每个窗口都完全采用纯 MVVM。

## 应用发现和启动

启动/手动刷新时在后台 STA 线程枚举用户与公共开始菜单、用户与公共桌面以及 `shell:AppsFolder`。快捷方式保留路径和参数，Store/打包应用保留可解析的应用用户模型 ID。自动分类只产生建议，发现结果合并保留用户分组、顺序和隐藏记录；隐藏记录作为 tombstone 留存，防止下次扫描重新出现。

启动使用 Windows Shell 处理真实目标。窗口匹配优先使用可读取的真实进程路径/应用身份；存在不可读取、代理宿主或多配置实例的边界。无法准确匹配时宁可不亮运行指示点，也不以单纯进程名猜测。前台切换遵守 Windows 的前台限制，不能保证跨权限或受保护应用一定成功。

## 线程与资源

- 图标在后台获取，转换为冻结的 WPF 位图后跨线程交付；缓存复用，避免重复 Shell 解析。
- `SetWinEventHook` 提供窗口/前台事件，事件合并后更新状态。无固定频率全窗口轮询。
- 自动隐藏只在鼠标离开后启用一次性延迟，空闲没有持续动画帧订阅。
- 主题/电源/显示器变更通过系统事件响应，退出解除订阅、取消钩子并释放托盘与图标资源。
- 普通非分层 WPF 窗口以 Windows 11 DWM Desktop Acrylic 为回退。0.4 的液态层在内存中采样后方区域，执行曲边像素偏移与内部柔化；活动管理窗和鼠标停留的 Dock 可限频更新，空闲 Dock、隐藏和不活跃窗口停止更新。短暂的本进程捕获排除在 finally 恢复。省电时禁用这层；详见 `WINDOW-BACKDROP.md`。
- 0.5 的 `GlassRim` 在原有折射层上绘制窄幅的边缘流光。实际变化的指针坐标触发短生命周期 `DispatcherTimer`，间隔 34 ms；最后一次有效输入后最多 620 ms 停止，鼠标离开后最多 180 ms 消退。重复合成的同坐标 MouseMove 不续期。隐藏、卸载、不活跃或减少动态效果时立即停止；没有常驻 `CompositionTarget.Rendering` 订阅。该层只移动二维反光，不驱动背景像素的流体模拟，后方采样仍由 `LiquidGlassSurface` 单独控制。
- 过渡动画只作用于内容层，保留 HWND 的不透明度与原生合成方式。搜索框使用随输入、选区和焦点更新的静态光标，解除 WPF 光标子元素的重复视觉动画，没有光标刷新计时器。该视觉树兼容处理基于当前固定的 WPF 10 版本，升级运行时或 TextBox 模板时须复测输入和资源占用。

## 颜色与名称字体

`Theme.Apply` 统一生成强调色、选中状态与控件资源。`Accent` 只接受 `Lagoon`、`Jade`、`Amber`、`Iris`，界面对应潮蓝、青瓷、琥珀、烟紫，各自有深浅色值；边缘反光使用同一强调色，不维护独立的控件调色板。旧配置缺少这些字段时使用默认值，不要求迁移系统主题。

名称字体由 `AppController.NameFont` 给出。`FollowSystemIconFont=true` 时读取 `DesktopFontService`；否则使用本机字体家族、10–40 DIP 字号、粗体及斜体设置，空字体名使用界面字体回退顺序。WPF 动态资源应用到应用库、桌面集名称和 Dock 提示。设置页的预览使用实际应用名称和同一字体值；滑块拖动只即时改预览，提交交互后保存，避免每个微小步长都写文件。

手动字体是 LumaDock 的显示偏好，不调用写入 Windows 全局字体的 API。配置导入对字体名长度、控制字符和 URI/路径分隔符作校验，避免家族选择成为外部字体文件加载入口。大字号通过 `AppGridLayout` 改变列数上限及两行名称高度，DPI 放大仍交给 WPF。

## 本地数据

默认 `%LOCALAPPDATA%\LumaDock`，诊断可通过 `--data-dir` 隔离。`config.json` 的模式版本为 1。写入临时文件并刷新到磁盘后替换；已有配置备份到 `.bak`。损坏文件原样保留后回退备份或默认状态，高版本配置拒绝读取。导入应校验和归一；导入设置不能自动更改真实启动项。日志轮转，不主动上传数据。

## 系统设置原则

开机启动与桌面图标显示仅在用户点击对应设置并确认后改变。开机启动通过当前用户启动文件夹自有快捷方式实现；桌面显示操作是 Explorer 窗口显示状态调整，不删除文件。导入、重置和自动化测试均不授权系统设置变更。

## 贡献工作流

1. 用 Windows SDK 环境执行 `scripts/build.ps1`。
2. 修改 Core/Storage 后运行 `scripts/test.ps1`，新增测试应验证业务契约与错误路径。
3. Shell、DPI、窗口交互改动需真实 WPF 桌面测试，记录 OS、显示器、缩放、目标应用及结果。
4. 发布前执行自包含构建，并从发布目录运行测试实例。性能结果保留原始 CSV/JSON，不把 Release 编译通过写成 UI 验收通过。
5. 构建产物、SDK、日志和临时测试数据不进 Git。GitHub Actions 在 Windows runner 构建整个解决方案、运行确定性的 Core/Storage、像素与布局组件测试，生成便携包；不把 CI 通过作为真实桌面、系统字体修改或性能验收。发布远程仓库前检查提交内容及发行附件，避免包含本机配置与背景截图。
