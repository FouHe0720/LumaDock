# 架构

[开发与构建](DEVELOPMENT.md) · [Windows 集成](WINDOWS-INTEGRATION.md) · [材质实现](WINDOW-BACKDROP.md)

LumaDock 是单进程、普通用户权限的 Windows WPF 应用，目标框架为 `net10.0-windows`，运行架构为 x64。

## 模块

| 模块 | 职责 | 资源边界 |
| --- | --- | --- |
| App | 生命周期、托盘、热键、Dock、管理窗口、主题与设置 | WPF 状态与交互留在 UI 线程 |
| Core | 目录、稳定 ID、合并、搜索、自建栏目、设置校验与图像算法 | 不依赖 WPF、Shell 或磁盘 |
| Windows | Shell/COM、图标、启动、窗口跟踪、屏幕和原生背景 | 释放句柄、COM 引用和事件钩子 |
| Storage | JSON、原子替换、备份、恢复和日志 | 配置版本校验，日志轮转 |
| Tests | 组件契约、真实窗口与系统集成 | 隔离测试配置，不擅自更改系统偏好 |

管理窗口使用 `AppTileViewModel` 绑定名称与图标，应用控制器管理命令和持久状态。小型布局与交互采用代码构建 WPF 控件，核心业务与 Windows 交互保持项目边界。

## 发现、合并与启动

启动或手动刷新时，后台 STA 线程枚举开始菜单、桌面快捷方式和 `shell:AppsFolder`。快捷方式保留路径与参数，注册应用保留可解析的应用用户模型 ID。扫描结果合并时更新启动元数据，保留自建栏目、顺序、固定、隐藏状态和自定义图标来源。

扫描只覆盖这些受支持的注册入口和手动路径，不遍历整块磁盘，也不将它们当作设备上所有可执行文件的完整清单。未注册的便携软件由用户手动添加。

`ApplicationAvailability` 区分已确认存在、已确认不可用与无法确认。已失效的文件或完整 AppsFolder 枚举确认不存在的注册入口标记为不可用，UI 和 Dock 暂不显示；其自选图标、栏目及固定顺序仍保留，恢复后可以重新出现。读取失败或不完整枚举不会仅凭缺席清除记录。普通文档、文件夹快捷方式尽可能排除；MSI 安装器快捷方式通过只读组件路径解析，不触发安装或修复。

用户主动隐藏的记录另存为持久标记，避免下次扫描重新出现。UI 搜索按完整输入字符串匹配名称或启动路径；Core 的词项搜索 API 是独立组件接口。

`AppIdentity` 比较启动目标、有效参数、URL 与 AUMID；不同非空工作目录、不同宿主应用标识和有意义的参数保持独立。启动来源统计字段只在可识别范围内忽略，网页与协议入口保留真实目标。旧 ID 与 Dock 固定项自动映射到保留记录，显示名称相同本身不会导致合并。

展示层另由 `ApplicationPresentation` 将同名、指向同一已存在本地可执行文件的记录组成一张卡片，不合并或改写原始启动记录。打包身份与通用宿主不参与这层聚合。路径存在性仅在完整视图重建时按唯一可执行文件检查一次；输入搜索时使用已缓存的组与顺序，不重复访问文件系统。

聚合卡片和 Dock 的“启动方式”菜单保留每条记录的来源、参数与工作目录。显式选择调用 `LaunchNewInstance`，直接交给 Shell，不被普通点击的已有窗口激活逻辑替代；程序自身仍决定窗口和进程行为。Dock 优先采用最早保存的有效固定记录，其他方式只占用菜单，不重复显示图标。放入栏目、隐藏与取消固定按整组处理，原始启动 ID 继续保存。

`.url` 文件按有界 INI 读取取得 `LaunchUri`，只用于身份比较，不请求网络或改变启动方式。URI 的方案与主机按标准归一，路径、查询和片段保留大小写差异。旧 URL 记录在合并前补齐身份。同一直接 Win32 可执行文件与参数的旧、新快捷方式 AUMID 可视为别名；共享宿主、浏览器和不同打包应用身份仍保守处理。

MSI 目标读取使用 [MsiGetShortcutTargetW](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msigetshortcuttargetw) 和 [MsiGetComponentPathW](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msigetcomponentpathw)，取得已安装组件的真实可执行目标，避免把安装器图标路径当作程序。只查询现有元数据，不调用安装、修复或组件配置接口。

启动交由 Windows Shell。窗口匹配使用可读取的真实可执行文件路径或应用身份，无法准确识别时不显示运行指示。窗口激活遵守 Windows 前台与权限限制，失败会明确返回，不注入目标进程。

## 统一列表与自建栏目

管理窗口只有一个“应用”入口。开始菜单、桌面、注册入口和手动应用共用同一份去重后的记录，不再为桌面来源单独建页面。`IsAvailable` 与 `Hidden` 分别控制可用性和用户隐藏状态。

`Categories` 初始为空，扫描及配置归一化都不再调用自动分类。`CreateCategory`、`RenameCategory` 和 `DeleteCategory` 管理单层虚拟栏目；删除只清除相关应用的栏目归属，不移除应用、固定项或文件。应用可通过拖放或菜单归入栏目，列表排序与栏目归属分别保存。

`OrganizationVersion=1` 表示已完成一次旧版整理迁移：移除旧内置分类及对应归属，保留能够识别的自建栏目。`CategoryIsUserAssigned` 标记手动归属，`CategoryRuleVersion` 只用于兼容旧数据；遗留分类建议方法不再参与扫描或日常保存。新栏目及删除后的状态不会被扫描重新生成。

## 线程与空闲行为

- 图标在后台 STA 中提取，冻结位图后交付 UI，使用有界缓存；可见图标按 DPI 请求合适的像素尺寸。
- 窗口变化通过 `SetWinEventHook` 监听并合并，不按固定频率轮询全部进程。
- Dock 自动隐藏只在离开后启动一次延迟；停稳后无持续动画帧回调。
- 主题、电源、会话与屏幕变化通过系统事件更新，关闭时释放订阅和句柄。
- 管理窗口保留普通非分层 HWND 与 DWM 原生合成；Dock 单独使用逐像素透明的小窗口，为放大图标预留透明空间。

搜索框的视觉光标随输入、选区和焦点变化更新。仅移除视觉动画不足以停止 WPF 保留的闪烁根时钟，因此 `StaticCaret` 在几何更新后停止自身输入框的该时钟，并在失焦、卸载和字体布局变化时清理。处理由输入事件、一次空闲调度与聚焦期间的被动布局通知触发，不增加周期轮询。

这处兼容处理按确切类型与字段类型保护，只读取当前 WPF 运行时的光标时钟，随后调用公共 `ClockController.Stop()`；不写私有字段、不移除原生插入点、不更改 Windows 闪烁设置。字段不可用时记录一次并保留输入功能。实现依据见 [WPF CaretElement](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Documents/CaretElement.cs)；升级运行时或模板后需重新验证光标、输入、辅助功能与资源占用。

## Dock 轮廓与悬停

Dock 使用原列表间隙计算插入位置，在拖拽时显示插入标记。桌面文件异步解析后批量提交；源文件不移动。内部拖动立即进入 OLE，只传应用 ID，不准备磁盘文件。`DockTransferData` 延迟提供 `CF_HDROP`：外部 Shell 请求文件数据时，才在自有目录生成真实快捷方式副本；只允许 Copy，避免外部目标移动源文件或创建依赖暂存路径的链接。拖拽结束后再执行推迟的 Dock 重建。

可见 Dock 可能包含聚合后的启动方式，同时略过暂不可用的固定记录。插入位置先按可见图标计算，再以相邻有效记录为锚点映射回原始固定顺序，避免把隐藏记录或其他启动方式误算为鼠标位置。暂不可用的固定项仍保留在配置中。

普通程序保留参数和工作目录，打包应用使用真实 Shell PIDL；导入时读取快捷方式目标的权威 AUMID 属性。暂存文件保留七天，以兼容异步完成的 Shell 目标，只在下一次导出时清理符合条件的自有 GUID 目录，不设置后台清理轮询。

`DockShape` 提供 `Capsule`（胶囊）、`Pebble`（卵石）与 `Rail`（轨道）。`DockPlate` 使用静态矢量轮廓、细边缘、窄阴影和强调色嵌线；卵石采用不对称圆角，轨道具有更薄的底座和较直的边。动态模式用真实半透明底座，静态模式的采样表面按同一轮廓裁切。

Dock 的 `AllowsTransparency=true` 仅用于这一个小窗口。底座与图标分层，图标活动区在朝向桌面内部的一侧留出空间，长轴两端也预留放大余量；可滚动容器内的布局计入这些空间。形状选择不改变应用排列，四边位置共用同一组交互规则。

悬停由真实指针位置计算余弦衰减权重，控制图标缩放、向内抬起、邻近图标微移和柔和底衬。WPF 变换使用独立的 16 ms 计时器插值，接近目标后停止；每次鼠标事件只更新目标值，不为每个图标反复创建动画时钟。相同指针位置不续开动画，离开后回到原位，隐藏、重建、关闭或减少动画时清理计时器。计时器间隔是调度目标，不代表已验证的帧率。

0.10 的插值按实际经过时间计算，响应时间常数为 54 ms，快速改变指针方向时沿当前姿态继续收敛。底座额外预留浅层倒影空间，放大余量与点击区域仍由同一套四边布局计算。

`DockReflection` 直接绑定真实图标的 `ImageSource`，共享已冻结的缓存图像。绘制时以固定玻璃平面镜像，使用冻结裁切和绝对坐标渐隐遮罩，仅绘制一段浅倒影；图标抬起后，倒影位置和强度同步变化。非方形图片保持 Uniform 比例。它不复制位图、不截屏、不使用实时 VisualBrush，也没有独立帧回调。

倒影由 `IconReflection` 与 `ReflectionStrength` 控制，强度范围 0–.5，默认 .24；省电和高对比度下关闭。源图标异步更新时，绑定同步更新倒影。空闲、隐藏与关闭时没有倒影动画计时器需要续期。

## 材质与流光

`LiveGlass=true` 是默认动态路径。`LiquidGlassSurface` 清空静态位图、取消旧任务并停止节流计时器，不在应用中循环截取或重放后方画面。管理窗口由 `WindowBackdrop` 使用普通非分层 HWND：默认 `LiveGlassStyle=Clear` 以扩展透明客户区和半透明底色保留后方细节；`Frosted` 使用 DWM Desktop Acrylic 柔化画面。Dock 使用自己的分层窗口与真实 alpha 底座，由系统合成后方内容。系统不支持原生路径时按条件回退，不保留旧采样帧冒充实时背景。

清透采用 `DwmExtendFrameIntoClientArea(-1)`、透明合成目标与 backdrop type 1；磨砂采用 backdrop type 3。`BackdropStatus.ClearActive` 与 `AcrylicActive` 分别标识实际应用的原生路径。清透的 `BackdropOpacity` 范围为 .25–.9，默认 .65，只调整管理窗口底色 alpha；Dock 仍使用自己的透明度。两种样式与浓度立即应用并持久化。当前清透实机验证范围限于记录中的 Windows 11 环境，不推定所有驱动或 Windows 10 都有相同表现。

Dock 的 `Opacity` 在界面称为“Dock 浓度”，范围 .15–1，默认 .70，控制玻璃底色的非线性浓度，不是直接给整窗乘以 alpha。旧配置第一次迁移时，仅将旧默认值 .88 调为 .70，其他值保留。图标自身不随底色变淡；关闭材质、省电或高对比度时保留可读背景。

`LiveGlass=false` 选择静态折射。打开、激活、移动、尺寸或相关背景事件经 80 ms 合并后，在后台采样一次有限区域，再执行曲边像素位移和内部柔化。平时保留画面，不持续追踪动画；同尺寸复用位图，相同场景可跳过图像计算。静态读取资源延迟创建，切回动态时释放。任务以各自的取消源结束，代次检查阻止旧任务回写。

`GlassRim` 独立绘制分层细边缘及短时反光。有效指针位置变化触发 34 ms 间隔的 `DispatcherTimer`，最后一次输入后约 620 ms 停止，离开后约 180 ms 消退。重复的同坐标输入不续期；隐藏、卸载、不活跃或关闭动效时停止。没有常驻 `CompositionTarget.Rendering` 订阅，也不执行流体模拟。

系统动态合成、静态光学、边缘流光与图标悬停互相独立。两种背景模式都可使用图标放大和短反光；动态模式不执行实时曲边像素折射，也不承诺系统合成的固定帧率或延迟。具体支持、采样并发与回退条件见 [材质实现](WINDOW-BACKDROP.md)。

Dock 的静态边缘统一由 `DockPlate` 绘制；流光接收同一底座的冻结轮廓，展平和弧长查找表只在布局变化时重建，避免每帧处理整条路径。设置应用通过单次持久化与重建更新 Dock。

## 图标来源

默认图标来自本机 Shell。`IShellItemImageFactory.GetImage` 使用正确的 `SIIGBF_ICONONLY`，提取应用图标而非文件缩略图，保留原始资源的边框、底色、留白与透明边缘。

提取使用 `SIIGBF_ICONONLY | SIIGBF_BIGGERSIZEOK`。默认来源依次尝试已存在的快捷方式或本地启动文件、AppsFolder 应用身份或启动路径、可执行文件路径，优先保留快捷方式自己指定的图标。资源不可读时允许后续请求重试，不把一次失败永久保存为缺失图标。

`AppEntry.CustomIconPath` 可覆盖 LumaDock 的显示来源。用户在应用列表或 Dock 选择本地 `.ico`、`.png`、`.jpg`、`.jpeg`、`.exe`、`.dll` 或 `.lnk`；图像文件有界解码，程序与库只提取图标资源。选择或恢复图标保存管理记录，不修改源文件或原快捷方式。配置归一化拒绝网页、网络共享、设备和相对路径；来源不可用时尝试系统图标。

缓存键包含启动、可执行文件、自定义图标三个路径的修改时间与长度，以及应用身份和请求像素尺寸。同键并发请求合并提取，缓存最多保留 256 项；同路径文件更新后，下次请求会使用新版本。图标透明 alpha 和传统 ICO 掩码按源资源保留，不做黑色抠图。

自定义路径保留在本地 JSON 中，并随配置导出；不复制图标文件，也不主动上传。导出到其他设备或公开分享时，需重新检查路径与私人信息。

## 主题与字体

`Theme.Apply` 统一生成控件资源，深浅主题使用各自的强调色值。按钮、选中状态、Dock 嵌线和边缘反光共享颜色资源。

| `Accent` | 显示名称 |
| --- | --- |
| `Lagoon` | 潮蓝 |
| `Jade` | 青瓷 |
| `Amber` | 琥珀 |
| `Iris` | 烟紫 |
| `Rose` | 玫瑰 |
| `Graphite` | 石墨 |

形状与配色立即应用并持久化。缺少形状字段的旧配置使用胶囊；未知或空值回退到 `Capsule` 与 `Lagoon`，保留原有应用、自建栏目和固定顺序。

`AppController.NameFont` 返回系统图标字体或用户自选家族、字号与样式。`ApplyNameFont` 更新 `AppName*` 资源，再由 `Typography.Apply` 分发 `UiTextFamily`、`UiTextWeight`、`UiEmphasisWeight`、`UiTextStyle` 与主要文字颜色。侧栏、栏目、标题、搜索和设置控件使用同一套家族、字重与斜体，标题与选中标签的字重至少为 600；图形符号固定正常样式。界面文字保持各自的字号，只有应用名称与 Dock 名称提示直接使用图标字号。

设置预览使用相同字体值，滑动时即时显示，提交交互后保存。大字号由 `AppGridLayout` 调整列数和两行名称空间，DPI 缩放交由 WPF。`DesktopFontService` 只读系统图标字体，在系统通知或窗口激活时刷新；数值不变时不发更新，无常驻轮询。动态资源让已有控件响应字体变化，不因此保存配置或重建 Dock。

`TextColor` 为空时按深浅主题生成主要文字颜色，自选色只接受 `#RRGGBB` 并归一为大写。主要侧栏、栏目、标题和应用名称使用该颜色，辅助说明、计数与强调色按钮保留独立资源。主题切换保留自选色，选择自动则重新使用主题色；高对比度覆盖为系统窗口文字颜色。自选色没有自动对比度修正，用户可恢复自动配色。

手动字体与文字颜色只写入 LumaDock 配置，不调用修改 Windows 全局字体的 API。配置导入检查家族长度、控制字符和 URI/路径分隔符，避免把家族选择变成外部字体加载入口；颜色校验拒绝透明色、资源表达式及任意外部来源，空值或无效色值回退自动。

## 持久化与系统操作

默认数据目录为 `%LOCALAPPDATA%\LumaDock`，可通过 `--data-dir` 隔离。0.10 使用模式版本 2，可读取并迁移模式 1。写入临时文件并刷新到磁盘后替换，已有配置备份为 `.bak`。损坏文件原样保留，再回退备份或默认值；较新配置拒绝向下覆盖。0.9 不能读取模式 2，回退旧程序时需要升级前的备份或独立数据目录。日志轮转，不主动上传。

开机启动与桌面图标显示仅在用户操作并确认后改变。导入和恢复默认值不授权系统修改。开机启动使用当前用户启动文件夹内的自有快捷方式；桌面显隐调整系统桌面窗口的显示状态，不移动文件。
